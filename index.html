Why I build the checks

At Finalyse I build Monte Carlo pricers for OTC derivatives and structured products: Hull-White, lognormal and hybrid models, their calibration and Greeks, and the SQL and VBA that keep the runs moving.

What I enjoy most is the second look. A price is only useful if you know where it stops being right, so each project here comes with its own test: Risk Hub compares every figure with an independent reference, and the neural pricer has a validation report that says plainly where it can be trusted.

riskhub-engine, the library behind Risk Hub

2026

Market, credit, counterparty, FRTB, liquidity, rates and model risk as plain Python functions. Each one is a line-for-line port of the site’s JavaScript engine, and the two are checked against each other on shared fixtures.

pip install riskhub-engine
# a GARCH-t sample, then three ways to measure and test its risk
from riskhub_engine import market, credit, options

r = market.simulate(1000, seed=7)
market.historical(r[-500:], 0.99)        # {'var': 0.0243…, 'es': 0.0298…}
market.garch(r[-500:], 0.99)             # GARCH(1,1) VaR / ES with the fitted a, b

bt = market.rolling_backtest(r, "historical", 0.99, 250)
n, x = len(bt["hit"]), sum(bt["hit"])
market.kupiec(n, x, 0.01)                # {'lr': 1.44, 'p': 0.23}
market.basel_zone(n, x, 0.01)            # 'green'

credit.merton(E=40.0, sigE=0.6, D=80.0, r=0.03, T=1.0)
options.bs(100, 100, 1.0, 0.2, 0.03, 0.0, "C")   # 9.41 and the Greeks

Hybrid HW1F / lognormal calibration

Bocconi final work

Calibrating a hybrid rates–equity model for long-dated structured rate products: Hull-White one-factor for the rates, a lognormal leg for the equity, checked by repricing the calibration instruments.

Why it matters

Long-dated structured rate products depend on how rates and equity move together. A model that fits each leg alone can still misprice the product, so the test is the joint repricing, and the Greeks that come out of it.
